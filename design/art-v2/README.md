# 时雨美术交付 v2：视觉母稿优先

这组文件是给后续开发、美术和测试 Agent 的视觉母稿，不是 OpenCode 运行时的 PNG 解码依赖。

## 主次参考

- `shigure-v3-master-crop.png`：主基准。直接从已批准的 v3 圆润像素角色板中提取，保留宽发、圆脸、双蓝眼、单侧细辫、短肢、低重心、分离双脚和桌宠比例。
- `shigure-v2-uniform-crop.png`：次基准。只用于确认水手服白侧板、红色长领结、红边短裙、袜口和短靴结构。
- `shigure-v3-terminal-seed-24.png`：从 v3 母稿最近邻缩到 24×24 的终端追踪种子。
- `shigure-v3-terminal-seed-16.png`：从 v3 母稿最近邻缩到 16×16 的紧凑追踪种子。
- `shigure-pixel-data.md`：无图像 Agent 可直接阅读的调色板、语义网格、行字符串和七状态动作契约。
- `shigure-pixel-data.json`：同一份数据的机器可读版本。
- `*-display.png`：深色背景展示版，方便人工快速比较；不作为运行时资源。

## 视觉结论

| 项目 | 对照 v3/v2 的结论 |
|---|---|
| 剪影 | v3 的宽头、两侧长发、圆肩、短肢和低重心被保留；没有舰装或机械结构 |
| 头身比 | 母稿优先采用 v3 的大头小身，终端 seed 只作为追踪起点，不把 seed 当成最终审美稿 |
| 脸/眼 | 柔和椭圆脸、分开的蓝色双眼和侧分刘海来自 v3；不是矩形脸或单条蓝线 |
| 辫子 | 右侧单条细辫落到胸前，母稿中可直接辨认；终端稿应优先保留其外轮廓钩 |
| 制服 | v3 的深色水手服与 v2 的暖白侧板、红长领结、红边短裙组合为正式服装基准 |
| 袜靴 | 两条独立黑色过膝袜、暖白袜口和深红棕短靴保留，脚底分离且不加地面阴影 |

## 给终端开发 Agent 的适配建议

1. 把 `shigure-v3-master-crop.png` 视为唯一视觉真源，把两个 terminal seed 视为人工 tracing 起点。
2. 构建阶段把母稿/seed 转成调色板索引矩阵；运行期使用矩阵或图集，不引入 PNG 解码器。
3. 首选继续使用半块 `▀/▄/█` 渲染，但允许把逻辑画布扩大到 32×32 后再压到侧栏；不要为了适配旧 24×24 而把头、脸、辫子和裙袜靴压成不可辨认的色块。
4. 角色身份优先于状态动作：每个状态先保持 v3 剪影和制服层级，再做眼神、头部、手臂或脚底的微动作。
5. 推荐状态母稿顺序：idle（本母稿）→ thinking（目光上移/轻侧头）→ working（双手向内、身体微前倾）→ waiting（抬头看向屏幕外）→ success（整体上移一逻辑像素）→ error（头低、眼窄）→ retry（左右轻摆）。
