# 视觉资产规范

> 状态：方向 A 圆润体型 v3 已选定；A 制服 v2 作为次选参考。  
> 本文约束后续美术 Agent 的最终七状态资产，不把概念图视为可交付精灵。

## 1. 角色定位

时雨在本项目中是一位安静、温柔、冷静、可靠，稍带忧郁感的少女型陪伴角色。她不是战斗展示角色，不通过舰装、武器或攻击效果表达身份。

情绪基线：

- 低能量但不困倦。
- 温和但不幼稚吵闹。
- 可靠而非严肃。
- 可爱来自微动作与轮廓，而非夸张表情符号。

## 2. 身份锁定

### 必须保留的识别点

按优先级排列：

1. 深棕/巧克力棕长发，不能画成纯黑或短发。
2. 单侧细辫子垂到胸前，是轮廓级识别点。
3. 明亮浅蓝/青蓝眼睛，眼神温和。
4. 深色水手服，领口和边缘有明确白色对比。
5. 胸前红色领结，在紧凑版中也至少保留一个高纯度红色像素簇。
6. 深色短裙、黑色过膝袜与深色短靴形成下身分段。

补充外形基准：脸部是柔和的小椭圆/轻瓜子形，不做成熟御姐锐角，也不做过度婴儿化的大圆脸；刘海自然侧分并带少量碎发，长发自然披散至胸前附近；红色领结可以保留较长的飘带尾部；短靴允许使用深红棕与近黑的两级像素表现。

### 必须省略

- 大型舰装、炮塔、鱼雷、机械背包和厚重装甲。
- 战斗姿态、武器挥舞、爆炸、炮火和海战背景。
- 可读文字、舰名、徽章和 logo。
- 与宠物分离的漂浮符号或 UI。

## 3. 比例与轮廓候选

### 概念 A：圆润陪伴型

- 约 2.2–2.4 头身；相对 B 更圆、更低，但不做夸张娃娃比例。
- 头部略宽、脸部柔和小巧，四肢短而清楚，保留少女感。
- 长发形成稳定的水滴/披风形轮廓。
- 辫子作为一侧突出的小轮廓钩。
- 优点：16×16 可读性强，宠物感明显，同时保留参考图的安静气质。
- 风险：若继续增大头部或缩短腿部，会重新滑向幼儿化，必须以当前修订版 A 为上限。

### 概念 B：纤细安静型

- 约 2.3–2.6 头身。
- 头部略窄，躯干和腿部更清晰。
- 长发与过膝袜形成纵向节奏。
- 优点：更贴近角色气质和制服轮廓。
- 风险：16×16 中面部和腿部容易拥挤。

## 4. 两档尺寸

### Regular

- 逻辑画布：24×24 px。
- 终端占用：24×12 cells。
- 角色建议实际占用：约 20–22 px 高，四周留安全边距。
- 必须能看到双眼/眼神方向、辫子、白边、红结、裙袜和鞋的主要分区。

### Compact

- 逻辑画布：16×16 px。
- 终端占用：16×8 cells。
- 是独立重绘版本，不得由 Regular 自动缩放。
- 强制保留：深棕长发轮廓、单侧辫子、蓝眼点、红结、深色制服与白边对比。
- 袜子和短靴允许合并为深色腿部块，但腿与裙必须可分。

### 共同几何规则

- 每一状态的脚底/身体基线稳定，success 跳起除外。
- 头部尺寸、辫子所在侧、红结位置与整体调色板保持一致。
- 不让头发、手脚或辫子接触/越过画布边缘。
- 不使用半透明像素；每个逻辑像素只有透明或一个离散调色板色。
- 不使用抖动噪点模拟大面积渐变，终端实际尺寸下会闪烁。

## 5. 调色板

建议将主体限制在约 12–16 个颜色索引内，最终数量由美术验证决定：

- 透明。
- 发色：深棕、主棕、柔和高光棕。
- 皮肤：主肤色、阴影、少量高光。
- 眼睛：亮青蓝、深蓝。
- 制服：近黑海军色、深灰蓝。
- 白边：暖白/浅灰，避免刺眼纯白占大面积。
- 红结：高识别红、深红阴影。
- 袜靴：近黑与深红棕可选。
- 轮廓：深色主体轮廓，以及暗主题下可替换的柔和浅轮廓。

主体调色板不随 OpenCode 主题改变。只允许外轮廓对比色在浅/深主题间切换，确保深色制服不融入 panel 背景。

## 6. 七状态动作规格

| 状态 | 必须读出的动作 | 可用动作 | 禁止替代 |
|---|---|---|---|
| idle | 平静、活着但不打扰 | 呼吸、眨眼、发尾/辫子微摆 | 挥手、工作、睡觉、大幅摇摆 |
| thinking | 正在思索 | 眼睛上移、轻歪头、手靠近下巴 | 漂浮问号、灯泡、文字气泡 |
| working | 专注执行任务 | 微前倾、双手小幅操作、眼神向下 | 字面奔跑、键盘/屏幕/代码道具 |
| waiting | 正在等用户 | 抬头、双手收拢、期待性轻摆 | 普通 idle、漂浮问号、敲击屏幕 |
| success | 温和庆祝 | 小幅跳起、微笑、辫子跟随 | 大爆炸、彩带、独立星星、过度舞蹈 |
| error | 困惑或低落 | 肩膀下沉、闭眼/苦笑、轻低头 | 红叉、警报、哭泣水滴、倒地 |
| retry | 正在重新尝试 | 振作、确认式左右看、轻握拳 | 与 thinking 完全相同、旋转加载图标 |

Waiting、Retry、Thinking 是最容易混淆的三组，最终联系表必须在无标签盲测中仍有多数人能够区分：

- Thinking：注意力朝内/朝上。
- Waiting：注意力朝向用户/屏幕外。
- Retry：动作有重复确认与重新振作的节奏。

## 7. 动画原则

- Idle 必须有可见微变化，不能复制同一帧。
- 所有循环的首尾姿势连续，不产生基线跳动或尺寸呼吸。
- Active 状态建议 4–6 FPS；Idle/Waiting 2–4 FPS。
- Success/Error 可采用一次性动作后停在收尾帧，状态控制器负责期限。
- Compact 可以减少帧数，但不能改变状态含义。
- 动画变化优先通过姿势、眼睛、头部、辫子和身体重心完成。

## 8. 禁止效果

所有状态默认禁止：

- 漂浮星星、问号、感叹号、爱心、汗滴、泪滴。
- 速度线、运动弧、残影、模糊和半透明光晕。
- 地面阴影、椭圆底座、落地尘土和冲击波。
- 对话气泡、代码、文件、显示器、键盘和 UI 面板。
- 角色之外的独立粒子或第二组件。

原因不是审美洁癖，而是这些元素会降低 16×16 可读性、干扰透明背景合并，并让状态含义依赖符号而非角色表演。

## 9. 概念样本要求

每个 A/B 概念板必须包含：

- 24×24 Regular idle 单帧，最近邻放大展示。
- 16×16 Compact idle 独立重绘，最近邻放大展示。
- 两档实际终端尺寸预览。
- 无舰装、无场景、无文字水印。
- 同一角色、同一辫子侧、同一制服与调色板。

概念板只决定头身比例、轮廓、脸部简化和关键颜色，不决定最终全部动画。

### 9.1 PNG、像素矩阵与终端输出的区别

本项目的“终端原生”指运行时输出路径，而不是要求概念图本身是一张终端协议图片：

```text
概念 PNG / 像素源帧
        ↓ 仅作为参考或构建期输入
24×24 / 16×16 调色板索引矩阵
        ↓ 运行时半块映射
ANSI 真彩色 + ▀ / ▄ / █ + sidebar_content
```

- PNG 适合让人选择比例、轮廓和配色，也方便美术编辑；它不应在运行时被解码。
- 最终可发布资源应是确定性的离散像素数据：透明索引、调色板、帧矩阵、帧率和循环信息。
- 如果后续美术 Agent 直接交付矩阵或索引图集，可以跳过 PNG 输入；不能跳过尺寸、透明、调色板和渲染 QA。
- 概念板底部的终端格预览只是说明 24×12/16×8 占用关系，不能当作最终 ANSI 字符串或已验证的半块矩阵。

- 两尺寸 × 七状态的源帧。
- 每种状态的正常尺寸联系表。

- 浅色/深色 panel 背景 QA 图。
