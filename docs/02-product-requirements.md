# 产品需求文档

## 1. 文档目的

本文定义 `opco-shigure` V1 要解决的问题、用户可见行为、范围和验收目标。开发 Agent 可以自主选择代码组织方式，但不得改变这里的产品语义与边界。

## 2. 产品目标

当用户在 OpenCode TUI 中工作时，右侧栏出现一个安静的时雨像素角色。她通过动作与短标签反映当前会话是在思考、执行工具、等待用户、重试、完成还是出错，让 OpenCode 增加陪伴感，同时保持状态可扫读。

项目不试图成为 Agent 控制台、养成游戏或桌面宠物平台。

## 3. 目标用户

### 主要用户

- 长时间使用 OpenCode TUI 的开发者。
- 喜欢像素艺术、二次元角色或轻度陪伴感。
- 希望一眼发现“正在工作”与“在等我”的差别。
- 使用现代终端，但不愿为宠物更换特定终端或安装桌面运行时。

### 非主要用户

- 需要跨多个 Agent 的监控和统计用户。
- 需要桌面悬浮窗、鼠标拖拽或复杂交互的用户。
- 需要在 OpenCode Desktop/Web 中展示图片宠物的用户。

## 4. 体验原则

1. **陪伴而非提醒轰炸**：默认不发声、不弹窗、不写入聊天。
2. **状态含义优先于花哨动作**：等待、重试、错误必须清楚区分。
3. **当前会话唯一**：宠物永远描述当前侧栏对应的会话。
4. **视觉质量优先于功能数量**：一个角色、七种状态做完整，再考虑扩展。
5. **失败不影响工作**：宠物功能是可丢弃增强层，任何异常都必须安全降级。
6. **本地与克制**：不读取会话正文，不联网，不记录生产力数据。

## 5. V1 用户故事

- 作为 OpenCode 用户，我打开有侧栏的会话时能看到时雨待机。
- 当模型开始推理或输出时，我能看到“思考”。
- 当工具或 Shell 正在运行时，我能看到“工作”。
- 当 OpenCode 等我批准权限或回答问题时，我能立即看到“等待”。
- 当 Provider 正在退避重试时，我能看到“重试”，而不是误以为卡住。
- 当任务正常结束时，我能看到短暂“完成”反馈。
- 当任务不可恢复地失败时，我能看到短暂“出错”反馈。
- 我可以从命令面板隐藏宠物、切换常规/紧凑尺寸、关闭动画。
- 当侧栏因终端太窄而隐藏时，宠物不占用聊天或提示输入区域。

## 6. 功能需求

### FR-1 侧栏展示

- 注册到 `sidebar_content`，不得替换 session title 或 footer。
- 在当前 OpenCode 侧栏的内容流中占用一个自包含区块。
- 默认常规尺寸为 24×12 字符格，标签另占一行。
- 紧凑尺寸为 16×8 字符格，标签另占一行。
- 宠物启用且侧栏可见时，七种状态均始终显示对应中文标签；动画关闭不隐藏标签。
- 不主动强制侧栏显示；侧栏隐藏时没有替代浮层。

### FR-2 七类状态

| 内部状态 | 中文标签 | 用户含义 |
|---|---|---|
| `idle` | 待机 | 当前会话没有进行中的任务 |
| `thinking` | 思考 | 模型在推理或生成自然语言内容 |
| `working` | 工作 | 工具、命令、文件或 Shell 操作进行中 |
| `waiting` | 等待 | OpenCode 正等待用户授权或回答问题 |
| `success` | 完成 | 一次活跃任务正常结束的短暂反馈 |
| `error` | 出错 | 一次不可恢复失败的短暂反馈 |
| `retry` | 重试 | Provider/会话正等待下一次尝试 |

### FR-3 配置与命令

固定配置合同：

```ts
type PetConfig = {
  enabled: boolean      // default true
  size: "regular" | "compact" // default regular
  animations: boolean   // default true
}
```

命令面板动作：

- `Shigure: Show/Hide Pet`
- `Shigure: Use Regular/Compact Size`
- `Shigure: Enable/Disable Animations`

命令应即时生效并保存到 TUI KV。V1 不需要专用设置页面，也不需要修改项目文件。

### FR-4 动画关闭

- 仍然监听事件并更新状态标签。
- 每个状态只显示其代表性首帧。
- 不启动或继续帧计时器。

### FR-5 故障降级

- 未知事件：忽略，不改变当前可信状态。
- 非法帧/缺失状态：显示内置静态 idle 占位。
- 渲染异常：捕获在插件边界内，必要时只显示文字标签。
- 插件卸载/热重载：释放全部监听器和计时器。
- 不允许宠物异常阻断权限、工具或消息流。

## 7. 非功能需求

### 性能

- 动画刷新不高于约 6 FPS。
- idle 可使用更低节奏，避免无意义重绘。
- 侧栏不可见、宠物禁用或动画关闭时停止帧循环。
- 运行时不解码大型图片，不引入 Electron、Canvas、Sharp 等重型依赖。

### 隐私与安全

- 零网络请求和遥测。
- 不解析用户提示、助手正文、工具输出、文件内容或路径。
- 只读取事件类型、会话 ID、工具生命周期和等待队列等状态元数据。
- 不注册模型可调用工具，不修改 system prompt，不影响权限结果。

### 兼容性

- OpenCode 1.18+。
- 需要 Unicode 单宽半块字符与 ANSI 颜色支持。
- 主路径不依赖终端图像协议，能自然穿过多数 tmux/SSH 链路。
- 对不满足字符/颜色能力的终端，只承诺标签可用，不承诺完整像素效果。

## 8. 成功标准

V1 可以称为成功，必须同时满足：

- 七种状态在真实会话中无明显误报或跨会话串扰。
- waiting 与 retry 能在一眼扫视中区别于 thinking。
- 24×24 与 16×16 版本在实际显示尺寸下仍能识别时雨关键特征。
- 宠物在浅色/深色主题和正式支持终端上不破坏侧栏布局。
- 用户能够在不重启 OpenCode 的情况下调整三项设置。
- 关闭/损坏插件不会影响 OpenCode 的正常工作。
- 安装后没有网络、外部进程和额外服务。

## 9. V1 明确排除

- 第三方角色包导入、在线画廊、角色下载与创作器。
- 多个内置角色、换装和皮肤系统。
- 经验、等级、进化、心情、饥饿、能量、成就和连续使用统计。
- 投喂、拖拽、点击反应、小游戏、随机对话和模型生成台词。
- 声音、系统通知、健康提醒和勿扰日程。
- WebSocket、HTTP、MCP、数据库和云端同步。
- 多 Agent、子 Agent 列表、任务进度和 token/cost 仪表盘。
- OpenCode Desktop、Web UI 或独立桌面窗口。
- Codex 宠物包兼容与 8×11 方向图集。
- 旧于 OpenCode 1.18 的兼容分支。

## 10. 后续但不承诺

内部资源抽象应允许未来增加角色，但 V1 不对外公布格式。只有当单角色版本稳定、视觉资产生产流程可重复、且用户确有需求时，才评估第三方角色包、多语言标签或桌面/Web 渲染器。
