冲突解决规则：

1. v3 决定体型、头身比、身体重心和宠物感。
2. v2 决定制服构造细节，但不能把 v2 较纤细的体型带回主设计。
3. 本文文字决定识别点、禁止项、尺寸和运行时约束。
4. 用户主参考图只补充外貌和制服灵感，舰装、炮塔、鱼雷、枪械和机械结构全部排除。

## 2. 一句话角色合同

时雨是一个约 2.2–2.4 头身、圆润但不幼儿化的少女型像素桌宠：深巧克力棕长发自然披散，柔和小椭圆脸，明亮蓝眼，单侧细辫垂到胸前；穿深炭黑/深海军色简化水手服，暖白领口与侧板，红色长领结，深色短裙、黑色过膝袜和深红棕短靴；气质安静、温柔、可靠，不带任何舰装或机械武器。

英文短合同：

> A rounded but not childish 2.2–2.4-head-tall Shigure-inspired pixel companion: long chocolate-brown hair, soft small oval face, clear blue eyes, one thin chest-side braid, simplified charcoal/navy sailor uniform with warm-white panels, long red neck ribbon, dark skirt, separate black thigh-high socks, and dark red-brown ankle boots. Quiet, gentle, reliable. No ship rigging or machinery.

## 3. 体型与轮廓（v3 主基准）

- 头部相对 v2 更大，但脸部不能变成无层次的大圆婴儿脸。
- 肩部和胯部是柔和的圆弧，躯干短而有宽度。
- 手臂、裙下腿部比 v2 更短，脚底位置稳定，整体重心偏低。
- 长发是两侧主要外轮廓，发尾自然落到胸前/上身附近；不能变成双马尾。
- 单侧细辫是独立轮廓钩，必须从头部一侧落到胸前；不能变成粗麻花或第二条辫子。
- 脸部保留少女感：小椭圆/轻瓜子轮廓、温和蓝眼、少量侧分刘海和碎发。
- 角色不是战斗姿势，不张腿、不摆攻击姿态、不做成熟性感比例。

## 4. 服装层级（v2 结构，v3 体型）

从上到下按以下层级理解，不需要查看图片：

1. **领口**：深色水手领，暖白边线形成清晰 V/领口对比。
2. **上衣主体**：炭黑或深海军色，短而宽；两侧有暖白侧板/腰侧块，不能画成整件白衣。
3. **领结**：胸前高纯度红色，结点小，尾部纵向下垂；Compact 中宁可减少结的横向细节，也要保留红色竖向识别块。
4. **袖/手臂**：可以用深色短袖或简化腕部深色块表达；不加入护甲、炮筒、机械手套。
5. **裙子**：深色短裙，裙摆有一条细红边；裙体必须和袜子分开。
6. **袜子**：黑色过膝袜，两腿独立；不能改成连裤袜、白袜或裸腿。
7. **短靴**：深红棕/近黑，简化鞋口和鞋底，不绘制复杂鞋带、扣具或装甲。

## 7. 状态帧的无图描述

所有状态都继承 v3 主体与 v2 制服，不重新设计服装：

| 状态 | 无图 Agent 可执行的动作描述 | 不得添加 |
|---|---|---|
| `idle` | 头身居中、双脚同基线、手臂自然下垂；只改变呼吸、眨眼、发尾或辫子 1 px | 星星、爱心、睡眠气泡 |
| `thinking` | 头部轻微上抬或侧倾，眼睛向上；身体仍保持圆润重心 | 问号、灯泡、文字 |
| `working` | 身体轻微前倾，手臂向内收，裙和脚基线稳定 | 键盘、代码、工具图标 |
| `waiting` | 头部朝屏幕外抬起，手臂收拢；红领结和白侧板不变 | 问号、对话框 |
| `success` | 小幅上跳，脚底最多离开 1 px；红领结/辫子跟随 | 彩带、星星、爆发效果 |
| `error` | 肩部下沉、头略低、眼睛变窄或闭合；服装颜色不变 | 红叉、警报、哭泣水滴 |
| `retry` | 小幅左右确认或握拳再放松；重复节奏稳定 | 旋转加载图标 |

## 8. 给不同 Agent 的直接指令

### 开发 Agent

- 不读取 PNG 来推断布局；使用 `PetState`、`PetSize`、manifest 和本文 token。
- v3 只提供比例方向，v2 提供制服层级；运行时使用编译后的矩阵。
- 不把概念板底部预览当作 ANSI 字符串。

### 美术 Agent

- 先做 v3 的 24×24 master idle，再独立重绘 16×16 compact。
- 以本文语义层为最低可辨识合同；如果自己的像素稿与 v3 图形感觉冲突，优先保证文字合同。
- 不增加舰装、机械、漂浮符号或场景；不把深棕头发画成纯黑。

### 测试 Agent

- 用 token 检查矩阵：`eye_blue`、`ribbon_red`、`trim_warm_white`、`sock_black` 必须在两档尺寸存在。
- 检查 v3 的宽头、短肢、低重心，不要用 v2 的较纤细比例作为失败标准。
- 在实际终端尺寸检查半块压缩后仍能分出头发、脸、白领、红领结、裙、袜、靴。

## 9. 文字验收清单

无多模态 Agent 交付前，逐条回答“是/否”：

- 是否使用 v3 的圆润体型，而不是 v2 的较纤细体型？
- 是否保留深巧克力棕长发、柔和小脸、蓝眼和单侧细辫？
- 是否保留 v2 的白色侧板、红色长领结、红边短裙、黑色过膝袜和深红棕短靴？
- 16×16 中是否至少看得到蓝眼、白边、红色块、深棕发和两只深色脚块？
- 是否完全没有舰装、炮塔、鱼雷、枪械、机械背包、场景和漂浮符号？
- 是否把 PNG 当作参考，而不是运行时解码依赖？

只要任一项为“否”，不得进入七状态批量制作或发布验收。
